## Feature Description

| Feature | Description |
|---|---|
| `Time` | Seconds elapsed since the first transaction in the dataset. Covers ~48 h. |
| `V1`–`V28` | **PCA-transformed, anonymised** features. Original features are confidential. All 28 are numeric. Because they are already PCA outputs, they are (approximately) decorrelated. This severely limits interpretability and non-linear feature engineering. |
| `Amount` | Raw Euro transaction amount. Highly skewed (heavy-tailed); most transactions are small. Log-transformed in the base feature set. |
| `Class` | Binary label: 0 = legitimate, 1 = fraud. Used ONLY for evaluation, threshold selection on val, and diagnostics — never for model training. |

## Duplicate Rows

- **Count:** 1,081 exact duplicate rows exist in the raw dataset (0.38 % of total).
- **Decision:** Duplicates are KEPT by default (`drop_duplicates: false` in `configs/config.yaml`).
  This avoids silent data loss and preserves the exact published dataset.
  The count is logged at load time via `src.data.load_raw()`.
- **Rationale:** The duplicates may represent genuine repeated small transactions
  (common in real card fraud datasets) or CSV artefacts. Without ground truth,
  dropping them is an unjustified assumption.
- **Impact:** Keeping them means some rows appear identically in train AND
  potentially val/test after the chronological split — this is noted as a
  known limitation.

## Split Policy

| Split | Fraction | Rows | Frauds | Base Rate | Time range (s) |
|---|---|---|---|---|---|
| Train | 60 % | 170,884 | 360 | 0.2107 % | 0 – 120,396 |
| Val | 20 % | 56,961 | 57 | 0.1001 % | 120,396 – 145,247 |
| Test | 20 % | 56,962 | 75 | 0.1317 % | 145,248 – 172,792 |

*(Source: `data/processed/split_manifest.json` — generated by `get_features()`.)*

**Method:** Rows are sorted by `Time` (stable sort), then cut at 60 % and 80 %
of the total row count. **No shuffling.** This is a chronological split that
respects the temporal ordering of real transaction data.

**Why chronological?** A random split would allow the model to "see" future
transaction patterns during training. Chronological splitting simulates the
real deployment scenario where the model is trained on past data and evaluated
on future data.

**Warning threshold:** If val or test has < 50 frauds, `src/data.py` emits a
loud warning and suggests the 60/15/25 split. At 60/20/20, val ≈ 98 and
test ≈ 99 frauds — sufficient for our purposes, but confidence intervals on
PR-AUC will be wide (≈ 100 fraud events). This is acknowledged in the report.

**Final decision:** Keep 60/20/20. Val has 57 frauds and test has 75 frauds —
both above the 50-fraud warning threshold, so no split change is needed.
However, 57 frauds in val gives wide confidence intervals on PR-AUC and
unstable threshold estimates. This is acknowledged in the results.

## Time Column Assumption

> ⚠️ **ASSUMPTION:** We assume `Time = 0` corresponds approximately to the
> start of a day (midnight). This assumption is used to derive the cyclic
> time-of-day features `sin(2π·(Time mod 86400)/86400)` and
> `cos(2π·(Time mod 86400)/86400)`. The dataset documentation does NOT
> confirm this; Time could start at any point in the day. The cyclic encoding
> is therefore an approximation of hour-of-day, not a verified fact.

## Known Limitations

1. **PCA anonymisation:** V1–V28 are PCA projections of undisclosed original
   features. We cannot interpret individual features (e.g. "merchant category")
   or engineer domain-specific features. This limits the feature engineering
   scope to mathematical transformations.
2. **Only 48 hours of data:** A single 48-hour window may not capture seasonal
   or weekly fraud patterns. The model may not generalise to different time
   periods.
3. **Severe class imbalance (0.17 %):** Accuracy is not a meaningful metric.
   Threshold selection is sensitive to the small number of frauds in val/test.
4. **Duplicate rows:** 1,081 exact duplicates are kept. Some may represent
   genuine repeated transactions; others may be CSV artefacts.
5. **Unknown reference time:** The `Time` column origin is undocumented,
   making exact hour-of-day recovery impossible.
6. **Static dataset:** No concept drift study is possible across the 48-hour
   window; a 5-block temporal PR-AUC analysis (if enough frauds per block)
   serves as a proxy.
7. **Privacy:** All V features are anonymised. No PII is present. The dataset
   is publicly available on Kaggle under the Open Database Licence.
